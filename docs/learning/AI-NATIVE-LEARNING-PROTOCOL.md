# AI 原生全栈按需学习协议｜不机械刷课，但要真正学会

> **目的**：你给出“我要开发什么 / 哪段代码报错 / 这个概念怎么理解”，AI 先识别当前问题、相关知识和已有能力，再提供专业原理、通俗比喻、官方资料、最小代码实验与独立验收。**不默认从零开始连续上课**。
>
> 边界：AI 可帮写脚手架、重复CRUD和测试框架，但**AI输出不是本人掌握**；真正的权限、数据一致性、故障恢复与生产上线必须有实测和人工判断。参见[AI Coding协作边界](AI-CODING-POLICY.md)。

## 1. 两个不同的入口

| 我现在知道什么 | 使用哪条路 | 核心动作 |
|---|---|---|
| 只知道“我要做一个网站/小程序/企业AI功能”，不知学什么 | 参考上游[BDL-P01](https://github.com/Xander-Xai/X-SuperPlay-AI-Learning-OS/blob/main/prompts/business-demand-learning/v1.0.0/01-business-demand-to-learning-goals.md) | 业务需求→用户/目标→模块→技能Gap，先确定当前最小交付 |
| 知道“我要学Spring事务/调试Vue状态”，不知怎么学 | 参考上游[ANL-P01](https://github.com/Xander-Xai/X-SuperPlay-AI-Learning-OS/blob/main/prompts/ai-native-learning/v1.0.0/01-github-ai-learning-research.md) | 指定技能节点→最低先修→官方章节→实战负例→独立验收 |

无论哪一个入口，都回到本仓的[需求路由](DEMAND-ROUTER.md)、[42节点知识图](KNOWLEDGE-GRAPH.md)、[权威资料](OFFICIAL-RESOURCES.md)和[会话卡](GAP-SESSION-TEMPLATE.md)。不要让上游六周 Track 和本仓原24周表同时驱动第二套日程。

## 2. 每次只针对当前阻断的一个 Gap

~~~mermaid
flowchart LR
  Need["真实需求或Bug"] --> Probe["AI协助前测：我会什么？"]
  Probe --> Gap{"存在可证实的知识缺口？"}
  Gap -->|没有| Implement["直接进入项目开发"]
  Gap -->|有| Graph["定位知识节点与最低先修"]
  Graph --> Sources["官方文档1–3小节+上游实训"]
  Sources --> Explain["专业定义+大白话+上下层关系"]
  Explain --> Lab["AI搭框架/本人关键实现+负例测试"]
  Lab --> Self["本人关AI独立改一项约束"]
  Self -->|未通过| Gap
  Self -->|通过| Implement
  Implement --> Evidence["留commit/命令/日志/测试/复盘"]
~~~

建议在实际任务前先回答两个问题：

- **会的部分**：如果我已经能关掉AI独立定位问题、编写针对性测试并解释修复，就不用再学一遍入门教程。
- **不会的部分**：如果只会让AI生成代码、却解释不了请求、事务或状态机，就立刻学习当前最低先修，并做一项真实错误实验。

## 3. 可直接复制的 AI Tutor 指令

~~~text
你现在是我的需求驱动全栈技术导师和代码审查员。我要做的业务/修复的问题是：【在这里填写当前需求或报错】。
我的代码/运行环境（如有）：【仓库、路径、语言、现有测试命令】。

请遵守我的 FullStack Learning OS：
- 优先查阅 docs/learning/DEMAND-ROUTER.md、knowledge-map.json、
  FULLSTACK-MENTAL-MODEL.md、OFFICIAL-RESOURCES.md 和
  UPSTREAM-ASSET-INDEX.md，沿用现有知识节点ID，不重新建立时间课表。
- 不要假定我必须先学完W1–W24。先基于当前需求判断必要能力，
  并区分“已独立会/有了解未验证/当前不会/当前不用”。
- 先给出本次业务链路：前端→HTTP/协议→API→业务→数据/异步→安全→部署，
  标注真正需要的节点、并行可选方案和最低先修（不强制学所有层）。
- 对每个要补的知识点，输出：
  ①专业定义与机制；②用大白话准确类比；③它在哪一层；
  ④与前后两个技术的调用关系；⑤为何选择它、何时不该用；
  ⑥官方原始资料的具体章节URL及上游现有学习材料；⑦一个最小负例实验。
- 如果我已有代码，先帮我分析真实代码/测试而不是重新造不相关Demo。
  AI可生成脚手架、重复代码、测试骨架；关键业务边界要让我理解并验收。
- 每次只推进一个最有价值Gap；给出可运行命令、预计观察现象、
  失败处理和停止条件。凡未执行都标NOT_RUN，不伪造通过。
- 最后让我关AI独立完成一个变化条件，记录环境、commit SHA、
  测试结果、根因与取舍；未通过继续补该Gap，通过就返回业务开发。
- 如果没有可靠官方材料或没有读取到仓库，不要虚构链接或源码。
  未经授权不操作真实账户/客户数据、付费API或生产服务。

先输出本次【目标能力节点→最低先修→专业解释→通俗解释→官方资料→最小实验】；
如果当前需求非常明确，直接开始，不要机械要求补充大量表单或重排长期课程。
~~~

## 4. AI 可以加速哪些环节，哪些不能糊弄

| AI 可以主动帮助 | 需要本人理解并负责 |
|---|---|
| 读代码、找相关调用链、提议可复现错误路径 | 业务规则/验收条件是否正确 |
| UI脚手架、重复CRUD、OpenAPI客户端生成 | 服务器权限、跨租户边界和数据正确性 |
| 给官方文档的具体入口、做术语对照 | 能解释专业原理，不能只复述比喻 |
| 生成测试骨架、数据夹具、对照候选方案 | 真正运行正负例、解释失败和修复 |
| 建立Mermaid图、总结错误、推荐下一Gap | 人工验收、变更取舍、真实部署与发布责任 |

这不是“必须所有核心代码手写一遍”。更高效的方式是**AI负责重复性实现，本人聚焦于可解释、可验证、可迁移的核心能力**。要做独立考核时，按[学习会话卡](GAP-SESSION-TEMPLATE.md)临时关AI完成新约束测试。

## 5. 示例：两个完全不同的学习顺序

**现有Vue项目列表竞态**：本次先F08(Vue watch/reactivity)→F03(JS Promise)→F01(HTTP Abort)，用上游Vue3+FastAPI Track中的真实项目片段做故障注入；不要先创建Spring、Next项目。

**新接到Spring API岗位任务**：B03(Java最低基础)→B04(Spring MVC)→B01(接口契约)，涉及数据库才补D01/B05；若用户只是要求接口成功，不强制先深入JVM GC、Vue或Docker大型编排。

**真正应当长期固定的是知识地图、错误记录和能够主动排错的能力，而不是固定时间课程。**
