# 全栈通用学习执行法｜从看懂到独立完成

> **定位：学习执行方法，不是第二份 ROADMAP、等级、课程或进度表。** 适配自 [AI-Learning-OS 的 METHODOLOGY](https://github.com/Xander-Xai/X-SuperPlay-AI-Learning-OS/blob/main/METHODOLOGY.md) 与 [通用学习执行法](https://github.com/Xander-Xai/X-SuperPlay-AI-Learning-OS/blob/main/docs/learning/learning-by-evidence.md)（核对日期：2026-11-19）。
>
> **本仓权威边界**：知识节点与最低先修由 [知识图](KNOWLEDGE-GRAPH.md) / [需求路由](DEMAND-ROUTER.md) 管理；个人等级只用 [AI-CODING-POLICY](AI-CODING-POLICY.md) 的 **L1 理解、L2 独立应用、L3 工程掌握**；学习状态唯一记 [PROGRESS](PROGRESS.md)；工程专项还须满足 [G01–G24](ACCEPTANCE.md) 的相关 Gate。**不把上游 L0–L4 数字直接映射成本仓 L1–L3。**

## 1. 到底什么才叫“学会”？

**给出一个未见过的新约束，能不依赖完整答案，解释原理、定位文件/调用链、完成最小改动、实际验证正常与异常行为、定位失败，并留下可复核证据。**

- 只认识术语、看完视频、读懂示例：**输入证据**，不能冒充独立掌握。
- 跟着教程运行成功、AI 生成代码、CI 变绿：**示例/项目证据**，不能自动升级为本人能力。
- 本人关闭完整答案与 AI 解题指导、按约定可查官方文档，独立完成新任务且记录命令和结果：才可申请**对应任务**的能力验收。
- 没有真实岗位/客户需求时，可以用合成练习，标记 **SELF_SET**；不伪称买家证据或实际交付。

## 2. 从结果倒推，而不是先刷 24 周目录

每次先写清六项：**Who**（为谁学）→ **Why**（为什么）→ **Outcome**（会做什么）→ **Evidence**（拿什么验）→ **Constraints**（环境/时间/授权）→ **Stop Rule**（何时停止）。

```text
当前需求 / 面试追问 / Bug
  → 先裸答或尝试（Diagnostic）
  → 42 节点 + 必要先修（Gap）
  → 精确官方小节 + 一个 worked example
  → 自己做最小任务（Practice）
  → 在当前有权限的项目应用一个纵向切片（Project）
  → 变化条件 + 正/负例 + 口述（Assessment）
  → 只沉淀验证过的知识、取舍和失败经验（Distill）
  → 返回需求；遇到新 Gap 再学
```

这一闭环保留上游 **TPPAD（Theory / Practice / Project / Assessment / Distill）**，但项目环节按当前任务选用：单个概念达到 L1 时无须制造项目；L2/L3 应选择与目标匹配的最小工程切片。已通过独立诊断的知识点直接跳过教程。现有 [42 张学习卡](NODE-STUDY-CARDS.md) 是知识索引，不是另一套必须顺次完成的课程。

## 3. 四种能力分别训练，不把“看懂”当“会做”

| 维度 | 我需要亲自证明什么 | 适用证据 |
|---|---|---|
| 概念解释 | 是什么、为何存在、输入输出、何时不用 | 不看笔记的讲解和反例 |
| 代码阅读 | 定位入口、参数、状态、依赖，预测正常和边界行为 | 调用链/数据流草图 + 运行前预测 |
| 实现与迁移 | 自己完成小需求，再改一个新约束 | 自己写的 diff / commit、变式记录 |
| 测试与排错 | 正常、异常/边界、安全（适用时），失败→原因→修复→复测 | 测试命令、exit code、断言、日志 |

**本仓等级的过关规则（不是上游量表换算）：**

| 本仓目标 | 最低证据 | 不强求的内容 |
|---|---|---|
| **L1 理解** | 闭卷解释机制、用途、输入输出、故障/不适用边界；能够阅读并预测一条相关流程 | 完整工程、独立修改大项目 |
| **L2 独立应用** | L1 + 本人实施一个最小功能、改变至少一项约束、真实运行正例和适用负例，能解释结果 | 复杂生产部署、源码级研究 |
| **L3 工程掌握** | L2 + 主动复现故障、独立定位修复复测、解释至少一项安全/一致性/性能/成本取舍，并做陌生场景复测 | 无关技术栈的强制通关 |

L2 的五项检查见第 6 节。对授权、安全、权限、生产发布等高风险任务，适用 [专项 Gate](ACCEPTANCE.md) 的硬门槛优先；某个最小练习过关不代表整门语言、全部 Gate 或真实生产交付完成。

## 4. 学概念、看代码、手敲代码、AI 代写怎么选？

| 面对的材料 | 学习者动作 | 不需要做的事 |
|---|---|---|
| 小型示例（约 5–30 行） | 先预测，再自己敲/重做关键逻辑，改一处条件 | 背全部标点或机械抄很多遍 |
| 组件/模块（约 50–200 行） | 画事件→状态→请求/返回；独立修改一个行为并测试 | 逐字重打一整份组件 |
| 后端服务/SQL 多文件链路 | 从路由/Controller 追到 Service/Repository、权限、事务；补一条测试 | 通读全部源码才开始动手 |
| 千行以上现有项目 | 看架构与入口，选一个纵向切片，沿输入→输出实测 | 全仓手敲 |
| 样板代码/配置 | AI/脚手架可以生成；本人审查接口、鉴权、异常、回滚、测试 | 将生成结果直接记为独立能力 |
| 算法/规则与性能 | 小输入手算、预测指标，再写最小实验验证 | 没有假设就盲目跑大模型/复杂集群 |

**以上行数是学习启发，不是硬门槛。** API 细节可以查官方文档。最终关键问题是：换一个条件，你能否自己改、测、解释？

## 5. 一次会话怎么教？（参考 40–90 分钟，绝非计时考勤）

1. **前测**：给定具体功能或故障，不看答案先说“在哪改、怎样测”；把不会的点记为 Gap。
2. **教概念**：专业定义 + 大白话但不失真 + 何时适用/不用；给最短示例和精确来源，先预测输出。
3. **半引导**：完整 worked example → 隐去关键步骤的填空 → 本人独立完成同类题。遇到困难先 H1 方向、H2 定位、H3 局部伪代码，只有用户要求或练习结束才 H4 完整答案。
4. **亲手改动**：关闭示例/完整答案，按约定工具范围自己做最小功能；不能运行时明确记为**纸面推演**。
5. **陌生变式**：换业务条件（例如按名称筛选改成名称 + 省份），不得仅复制参考答案。
6. **负例与复测**：先预测非法输入、空值、重复请求、越权或服务故障，再真实验证、修复和解释差异。
7. **记录与停止**：用 [GAP 会话卡](GAP-SESSION-TEMPLATE.md) 留真实证据；若未达目标，只补具体 Gap；达标便回到实际任务。

短期面试可将时间更多用于闭卷追问与真实代码穿透；长期工程能力则增加设计、实验、故障恢复。**不强制套用固定学习比例**。

## 6. 五项学习检查与状态边界

对目标 **L2/L3** 的工程练习，预先约定并逐项记录：

1. **概念**：本人脱离教程说明 Why / 输入 / 输出 / 边界。
2. **阅读预测**：指出修改位置和数据流，先预测正常及边界现象。
3. **独立实现**：写出最小功能，保存实际变更与原始运行证据。
4. **需求迁移**：在未见过的新约束下自行修改并解释影响范围。
5. **测试排错**：运行正例和适用负例；记录失败、根因、修复、复测。

**L1** 只按其理解目标验收，不要求假造代码/完整五项；**L3** 还要证实本人在故障和权衡下独立处理，不能只凭一次成功运行。对不适用的检查写 **N/A + 理由**；涉及权限、安全等风险不能用 N/A 绕过专项 Gate。

区分两个维度：

- **产物来源标签**：`AI_ASSISTED`（AI 提供关键实现/解法）、`EXPLAINED`（AI 解释/提示）、`INDEPENDENT`（按约定关指导独立操作）。接受提示的同一尝试不能再改称完全独立。
- **本仓进度状态**：只写到 [PROGRESS](PROGRESS.md)，使用现有 `NOT_RUN / IN_PROGRESS / PARTIAL / FAIL / BLOCKED / PASS_WITH_EVIDENCE`。延迟陌生变式通过可记录 `TRANSFER_VERIFIED` **作为证据标签**，不新建状态枚举或第二份台账。

提交证据至少包含：需求/节点、`repo@完整SHA`、版本/执行日期、本人 diff、命令/退出码、预期与实测、失败修复、AI 参与范围、独立复测与证据路径。**材料和模板新建后，个人状态仍是 NOT_RUN / UNASSESSED。**

## 7. AI 的三种协作模式

- **讲解**：专业 + 通俗解释，逐行讲 10–30 行核心示例，用户先预测。看懂仍未受考核。
- **练习教练（默认）**：先出任务/验收，允许逐级提示 H1→H4；用户未提交尝试前不主动贴完整解答。提示过的尝试标明 AI 参与。
- **工程协作**：可以产出完整脚手架与测试，但需要本人审查、执行、确认权限/数据与失败路径；**交付产物不等于个人独立掌握**。

独立考试必须由学习者明确切换：隐藏示例/答案、不接受实时解题提示，可按事先约定查文档。AI 可提供题目与审查，但不能声称自己证明了用户关闭了其他工具。复制用 [全栈 AI 教练提示词](AI-TUTOR-COACH.md)。

## 8. 两个落地例子（教学设计，非已执行成绩）

**Vue 3（F08/F03）**：阅读响应式搜索列表，预测 `ref`、`computed` 与 `@click` 的行为；本人做一个筛选组件；变式增加「仅 985」或「清空筛选」；验证空结果、快速切换、旧请求覆盖新结果的负例；记录浏览器 Network、测试输出和改动。参照 [J01 学习路线](J01-HAIBOTE-FULLSTACK-LESSONS.md)，实际练习均需另外留证据。

**Spring Boot（B03/B04/B05/D01）**：先画 `Controller → Service → Repository → DB`；亲自增加一个查询条件与对应 MockMvc/集成测试；变式加入分页或租户条件；测试非法参数与越权。只有涉及消息可靠性时再学事务 + Outbox（D03），分别验证「数据库成功/消息失败」与重复消费，不宣称单个单测证明生产最终一致性。

## 9. 复习、知识沉淀与停止规则

当日关资料复述；约 +1 天随机抽问、+3～4 天跨主题混合、+7 天新约束复测；**间隔是建议，按面试截止和遗忘调整**。只把核验过的定义/机制写入现有节点知识卡，把实验结果放在有权限的项目/会话证据里，把能力结论写在 [PROGRESS](PROGRESS.md)。不建立另一套知识图、影子考试或打卡系统。

**下一步决定方式**：未达目标 → 缩小到失败的一个 Gap；已达目标且满足相关 Gate → 停止此节点的本轮学习、返回当前需求；长期保持 → 安排一次延迟迁移，不靠刷时长获得“精通”称号。
