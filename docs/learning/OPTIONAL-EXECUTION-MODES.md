# 全栈学习可选执行模式｜按需求跳学、14天面试冲刺、8周项目实践

> **重要**：下面是三种**可选视图**，不是三套互相竞争的Roadmap或新进度台账。唯一总地图为[ROADMAP](../../ROADMAP.md)与[42节点知识图](KNOWLEDGE-GRAPH.md)；实际优先级由[需求路由](DEMAND-ROUTER.md)决定、独立完成状态只登记[PROGRESS](PROGRESS.md)。**14天、8周、144h是预算示例，不是完成保证，更不是每周强制按顺序晋级**。

> 补充：有些阻断并非框架本身，而是命令行/算法/调试/国际化/供应链/运营等[横向基础专题](CROSS-CUTTING-FOUNDATIONS.md)；它们与42节点归属联动，不要求先修完整框架路线。

## A. 默认：一个真实需求触发一次微学习（推荐）

~~~mermaid
flowchart LR
  Need["真实业务/JD/Bug"] --> Diagnose["已会还是不知道？"]
  Diagnose --> Node["定位42节点与最低先修"]
  Node --> Source["官方章节 1–3 小节"]
  Source --> Try["真实项目/最小受控实验"]
  Try --> Fail["故障/反例 + 独立变式"]
  Fail --> Evidence["留日志/提交/解释"]
  Evidence --> Return["回到业务，停止无关补课"]
~~~

- **我有真实代码**：先跑现有测试→确认缺口→阅读对应[学习卡](NODE-STUDY-CARDS.md)→修改业务代码→负例→复测。无需创建新的示例项目。
- **我没有业务代码**：选择[现存可运行小Lab](labs/README.md)或有授权的练习环境；先用最小实例理解机制，之后迁移到有变化条件的目标项目。
- **我已经会**：应接受当场独立复考；若能在新约束下说明原理、改代码且测试通过，直接回任务，不重复刷入门课。
- **我说不清楚机制**：只补当前节点最低先修；不要因为不懂Spring事务就退回去学完整Java全栈课程。

**AI Coding两模式**：学习时先给挑战和评分，再让AI评审、反问、提示；交付时可让AI生成脚手架/重复CRUD，但真实用户验收、授权、事务、上线与独立能力不能交给AI自动打PASS。参考[AI-Native协议](AI-NATIVE-LEARNING-PROTOCOL.md)。

## B. 可选“14天面试加速”｜目标是高频问答＋最小证据

> 适用于临近需要展示React/FastAPI/SQL/部署基本能力的岗位面试。**不代表14天学会全部全栈，不要求确实连续14天完成。** 与当前JD不相关的行允许跳过；已通过独立测评的模块直接用20题清单复盘，不强制再写一次Demo。

| 参考日期窗 | 面试目标与节点 | 不抄教程的实际动作 | 最低证据 |
|---|---|---|---|
| D01–D02 | HTTP/浏览器F01；JS/TS F03 | Network解释一次请求/跨域失败；逆序Promise竞态与Abort | Network记录+JS测试 |
| D03–D04 | React F04；HTML/CSS F02；API契约B01 | 表单、列表、分页、loading/error、旧请求处理；假接口契约漂移 | 可运行页面+状态反例 |
| D05–D06 | FastAPI B02；认证E03；接口设计B01 | Router/Service职责、非法输入、登录态过期、资源级拒绝 | API单测及401/403负例 |
| D07–D08 | SQL/PG D01；Redis D02（按需） | 两连接并发写＋EXPLAIN；验证缓存失效回源 | SQL命令、结果与解释 |
| D09–D10 | 纵向联调F04+B02+D01+E03 | 端到端登录/CRUD/文件上传，服务端权限不能只靠UI隐藏 | 浏览器→API→DB证据 |
| D11–D12 | Docker/Linux E02；CI E01；日志E04 | 干净环境复现、结构化请求日志、失败测试阻断CI | 环境/命令/日志/CI |
| D13 | 安全E03；故障与测试E01 | 越权、超时、重复提交、数据恢复或回滚中的目标相关项 | 失败→修复→复测 |
| D14 | P02/P03 系统设计；面试题 | 讲完整请求链路、架构权衡，挑5道最薄弱的题独立答辩 | 5题录音/书面+真实证据链接 |

**岗位特例**：面试JD若主要是Java/Spring，直接将D03–D06替换成B03/B04/B05的最小服务/权限/事务实验，**不把“先做React”写成通用前置条件**；Vue岗位将F04换F08。

## C. 可选“8周/144小时项目实践”｜每个主题是能力簇而非日历锁

> 参考上限预算：6天×3h×8周≈144小时。这个量不够保证一个人精通所有前后端、Java、Next、运维、AI。建议以**当前真实需求的一个产品或多个独立纵向功能切片**组织，不指定唯一项目。某阶段可提前开始、延长或免学，验收未过就回到对应技术Gap。

| 参考阶段 | 需要形成的能力 | 可选最小交付/负例 | 对应节点 |
|---|---|---|---|
| W1 Web/TS | 请求从浏览器到服务器可独立解释 | request取消/超时、跨域预检/旧请求竞态 | F01/F02/F03 |
| W2 组件/数据 | 真实可交互UI且错误可恢复 | React或Vue登录/表单/列表/分页；状态与缓存反例 | F04或F08/B01 |
| W3 API/权限 | 后端校验/契约可版本化 | FastAPI或Spring/Nest接口，401/403与坏输入 | B01/B02或B04/B07/E03 |
| W4 数据 | 并发一致性与查询成本可解释 | 表/迁移/复杂查询/执行计划/丢失更新 | D01/D02按需 |
| W5 跨层联调 | 浏览器/端点/DB的同一条链路有证据 | 登录＋CRUD＋上传/分页，一次可追踪失败 | F04或F08/B01/E03/E04 |
| W6 异步/AI（可选） | 长任务不丢、重试不重复；AI质量有证据 | 任务状态机/重试/SSE断连；RAG仅在业务需要时接入 | B06/F11/A01按需 |
| W7 交付 | 可复现部署与质量门禁 | Docker Compose、CI/E2E、权限/备份恢复演练 | E01/E02/E03/P03 |
| W8 运维/答辩 | 能测量、排障、解释架构取舍 | P95基线、Trace/日志、架构/ER/API/部署手册 | E04/P02/P03 |

**顺序不固定的例子**：正在修某后端事务Bug，可以直接从W4相关知识节点开始，完成SQL并发实验后回项目；正在部署一款静态工具站则先做W7/E02，完全不需要W3和W6。原[W1–W24历史教材坐标](../../ROADMAP.md)依然可索引所有知识，但本页不创建新W/新Gate。

## D. 时间如何分配（只是可调启发式）

**20%原理 + 60%实作 + 20%失败测试/复盘**，按每天3小时示例是36分钟/108分钟/36分钟；这是教学实践的资源分配建议，**没有证据证明对所有学习者最优**。数据库并发和可靠性项目可以将验证占比提高，先验丰富的部分可以直接做独立测评。

**一次会话必须留下四样东西**：
1. 目标能力及其在前后端哪一层、和谁协作的解释；
2. 实际源码/命令与运行环境，不用“AI写好了”替代运行；
3. 至少一个失败/权限/竞态/断连负例，且能复测；
4. 面对改变一个条件时，**关AI独立完成**，记录为何如此设计。

评价L1原理、L2独立应用、L3工程掌握，沿用[现有Gate](ACCEPTANCE.md)，**不设新的课程学分**。

## E. 什么时候从可选节奏回到业务

达到当前业务验收AC、核心负例通过、学习会话/真实代码有可核对证据时，停止当前补课。没有正式发布授权，即便CI成功也只能说“训练样例/隔离环境通过”。更完整的产品核查见[从需求到交付的12项清单](DELIVERY-LIFECYCLE.md)。
